# Структура данных — предложение на согласование

12.11.2026. Простыми словами: какие «списки» будут в базе и как они связаны.
Сейчас всё лежит в одной Google Таблице (одна строка = один артикул, 31 колонка). В базе то же самое
раскладывается по нескольким спискам, чтобы ничего не повторялось и связи были настоящими, а не по совпадению текста.

Решено (Вит, 12.11): база живёт на новом сервере рядом с Алексом; программа — главный редактор;
Google Таблица и Excel — выгрузка и обмен (технолог), а не источник.

## 1. Списки

### Бренды
Terragres, Golden Tile, Primavera, Brickstyle, Deseo…
- название;
- свой или импорт (для импорта — поставщик);
- папка бренда в каталоге на сети.

### Коллекции
Сейчас коллекция — просто слово в строке артикула. Станет отдельной записью.
- название;
- бренд (ссылка на список брендов);
- папка коллекции на сети и на Google Диске;
- эксклюзив сети (Епіцентр, Агромат… или пусто) — если эксклюзивна вся коллекция.

### Артикулы (главный список)
Одна запись = один артикул из 5 знаков, как сейчас.
- артикул;
- коллекция (ссылка);
- линейка: пусто / GT Basic / SlimStyle — сейчас это приписка к бренду в скобках, причём у одной коллекции
  бывают артикулы и с ней, и без неё (таких коллекций 59), поэтому линейка — свойство артикула, а не коллекции;
- назва декору;
- призначення, тип, формат (ширина и длина числами), товщина;
- колір (ссылка на справочник цветов — группа цвета берётся оттуда сама);
- поверхня, рельєф;
- застосування и тип дизайну — по нескольку значений из справочников (сейчас это текст через запятую);
- PEI, PTV, R;
- ректифікат и морозостійкість — считаются сами по правилам, вручную не правятся;
- статус: активный / выведен (с годом);
- эксклюзив сети — если эксклюзивен только этот артикул;
- год выпуска, комментарий.

### Заводские коды и упаковка
Новое. В файлах завода (выпуск, упаковка) код из 6 знаков: артикул + сорт (0/1 — первый, 3 — второй).
У разных сортов РАЗНЫЕ штрихкоды (так у 1739 артикулов из 2147 в файле упаковки), а в таблице сейчас
помещается только один.
- заводской код (6 знаков);
- артикул (ссылка);
- сорт;
- штрихкод;
- упаковка: шт в упаковке, м² в упаковке, вес 1 м², вес упаковки, упаковок на палете, м² на палете, вес палеты.

### Картинки и файлы
Сейчас их нет в данных вообще — программа каждый раз ищет по папкам.
- вид: фото товара / фейс / визуализация / живое фото / видео;
- коллекция (ссылка) и артикулы, которые на картинке (может быть несколько — на визуализации часто 2–3 плитки);
- где лежит: путь на сети и идентификатор на Google Диске;
- пометки из названия: main, CloseUp, AI;
- размер в пикселях, дата файла.
Отсюда же берутся картинки для менеджеров (с Диска) и, позже, для сайта и презентаций.

### Справочники
Короткие списки допустимых значений, с переводами (uk — основной; en, pl, ru):
цвета и группы цветов, поверхности, типы дизайна, применения, форматы (с правилом ректификата).
Новое значение добавляется один раз в справочник — и сразу доступно везде.

### История изменений
Каждое изменение записывается само: когда, кто, что (какое поле, было → стало), откуда (чат, файл упаковки,
файл технолога). Можно посмотреть историю артикула и откатить правку. Заменяет нынешние копии файла.

### Пользователи и ключи
- имя;
- роль: полная (Вит) или только просмотр (менеджеры);
- личный ключ — его можно отозвать у одного человека, не трогая остальных.

## 2. Что остаётся в программе на компьютере
- Задачи — личные, в базу не идут.
- Настройки, оформление, переписка.
- Журнал «запросы разработчику» — пока у Вита; для клиентской версии переедет на сервер (чтобы видеть замечания всех).

## 3. Что остаётся снаружи
- Сами картинки — на сети (оригиналы) и на Google Диске (копия). В базе только сведения о них.
- Google Таблица и Excel — выгрузка кнопкой в привычном виде «одна строка = один артикул» (чтобы скрипты сайта и каталога,
  которые читают Excel, продолжали работать) и загрузка Excel с показом разницы.

## 4. Как это связано
Бренд → Коллекции → Артикулы → Заводские коды (упаковка, штрихкоды)
                      ↘ Картинки (и от коллекции, и от артикулов)
Справочники → значения в артикулах. История — ко всему.

## 5. Ответы Вита (12.11) и что сделано
1. Сорта: храним только первый сорт (один заводской код и штрихкод на артикул).
2. Статус и сеть-эксклюзив — два отдельных поля. В выгрузке в Excel склеиваются обратно в «Актуальність».
3. GT Basic, SlimStyle — виртуальные группы товаров (артикул может быть в нескольких). SlimStyle — это Golden Tile.
4. Вид товара (плитка / сантехника / посуда…) — поле заложено, пока везде «плитка».

Найдено при переносе: в 24 коллекциях с одинаковым названием есть артикулы разных брендов (Joy, Ambra, Silent Shore…).
Поэтому бренд хранится у каждого артикула, а у коллекции — «главный» бренд (у кого больше артикулов).
Решено (Вит, 12.11): это одна коллекция, у неё может быть несколько брендов; бренд привязан к артикулу.
«Главный» бренд коллекции — только подсказка для нового артикула, если бренд не назван.

Сделано (0.4.0): база в программе (файл gt.db в папке данных), перенос из Google Таблицы/Excel кнопкой,
история каждого изменения, выгрузка в Excel в прежнем виде, копия базы раз в день (30 последних).
Когда будет сервер — тот же файл переезжает туда, программа ходит к нему.

Добавлено 13.11: у артикула год и месяц выпуска — это факт из файла выпуска (пусто = по документам есть, но ещё не выпускался).
Вторые названия коллекций для других рынков (Denver = Kassel, Польша) — пока списком в программе, позже поле в базе.
Справочники цвета и типа дизайна: у значения бывает упрощённое название в скобках («тауп (сіро-бежевий)», «граніт (камінь)») — в базе это отдельное поле значения справочника, по нему работает поиск.
